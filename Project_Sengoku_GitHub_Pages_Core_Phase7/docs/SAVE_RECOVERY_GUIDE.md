# Save Recovery Guide — Core v1.0 Phase 1

## 保存形式

各スロットは`project-sengoku-save` envelopeとして`localStorage`へ保存されます。envelopeには形式バージョン、保存時刻、FNV-1a 32-bit checksum、ゲームstateを含みます。checksumが一致しないデータはロードしません。

ゲームstateの`schemaVersion`は10、`gameVersion`は`core-0.95`のままです。Phase 1は保存媒体の信頼性を改善するフェーズであり、ゲームstate schemaを変更しません。

## スロットとバックアップ

- オートセーブ
- 手動セーブ1
- 手動セーブ2
- 手動セーブ3

各スロットは主データに加えて3世代を保持します。新しい正常セーブを書き込む際、正常な旧主データだけを第1世代へ移します。破損した主データはバックアップへ複製しません。

## 自動復旧

ロード順序は次のとおりです。

1. 主データ
2. 第1世代
3. 第2世代
4. 第3世代
5. 対応する旧バージョン保存キー

最初に見つかった正常データを移行・厳格検証し、主データが使えなかった場合は正常データを新しいenvelopeとして主スロットへ書き戻します。

## 手動復旧

セーブ管理画面では、正常なバックアップが存在すると「前回バックアップへ戻す」または「バックアップ復旧」を表示します。復旧後はその状態が現在のゲームstateとなります。

## 書込み安全性

保存時は次を実行します。

1. 現在stateの厳格検証
2. 複製stateへ保存日時と概要を設定
3. checksum付きenvelope作成
4. stagingキーへ書込み
5. stagingの完全一致読戻し
6. 正常バックアップの世代移動
7. 主キーへ書込み
8. 主キーの完全一致読戻し
9. staging削除
10. live stateの保存メタ情報更新

途中で失敗した場合、live stateの保存日時と概要は変更しません。

## 実行時チェックポイント

正常保存、正常ロード、JSONインポート時に、メモリ上へ直前正常stateを保持します。ゲーム処理後のオートセーブでstate不正を検出した場合、直前正常stateへ戻します。ブラウザを閉じるとこのメモリチェックポイントは失われますが、永続バックアップは残ります。

## JSON入出力

JSONエクスポートはenvelopeではなく従来のplain stateです。人が確認しやすく、旧バージョンとの移行経路も維持します。端末故障やブラウザ保存領域消去に備え、重要な進行は定期的にJSONエクスポートしてください。

## 制約

- `localStorage`自体が禁止・無効・容量超過の場合、ゲームは続行できますが永続保存できません。
- 3世代すべてが破損している場合、自動復旧できません。
- クラウド保存、オンライン同期、アカウント機能はありません。
